## 1. 這是什麼、不是什麼

### 這是什麼

一套**個人用的美股研究工具**，做三件事：

1. **追蹤**：每天自動抓取股價資料，存到你自己的電腦。
2. **分析**：計算技術指標、模擬各種買賣策略的歷史績效。
3. **驗證**：用嚴格的方法檢查「這個策略到底有沒有用」，並誠實地告訴你結論。

最終目標是**自動下單**，讓程式替你執行，不必每天盯盤。目前這個功能**已經做好、但刻意關閉**（原因見下）。

### 最終目標：全自動交易

**程式自己判斷、自己下單，你不必每天盯盤。** 這是這個專案存在的理由。
底下所有的驗證、風控、紀錄機制，都是為了讓那一天能夠**安全上線**，而不是為了阻止它發生。

| 能力 | 現況 | 路線圖 |
|---|---|---|
| 自動抓資料、算指標 | ✅ 已完成，每天自動執行 | 維持 |
| **產生買賣訊號**（今天該持有多少） | ✅ 已完成 | 維持 |
| 自動送出委託 | ✅ 程式已完成，**預設關閉** | 驗證通過後開啟 |
| 連接模擬帳戶 | ✅ 支援 | 維持 |
| 連接真錢帳戶 | ❌ 尚未開放 | **時機由你決定** |
| 更新頻率 | 一天一次（日線） | 若要盤中交易需另行設計 |

### 需要先講清楚的三件事

**① 系統會給你訊號，那是「規則的輸出」，不是「建議」**

執行 `trade.py` 時，畫面會直接告訴你：目標部位是多少、該買幾股或賣幾股。
未來自動化之後，這一步會直接變成委託單。**這本來就是系統該做的事。**

但要分清楚兩件事：

- **系統的訊號** = 一條寫死的規則，套用今天的數字算出來的結果。可以重播、可以稽核。
- **我（AI 助理）的推薦** = 不會提供。我沒有證照，而且沒有人真的知道明天哪一檔會漲。

所以你會看到「策略今天要求持有 100% SPY」這種輸出，
但不會看到我說「我建議你買 NVDA」。**要不要照著執行，是你的決定。**

**② 真錢那一步的開關在你手上**

目前程式在啟動時會檢查帳戶網址，只要不是模擬帳戶就拒絕執行。
這**不是永久限制**，而是「在還沒有東西值得跑之前，先別讓它有機會出錯」。

開啟的時機由你決定。合理的順序是：驗證通過 → 只記錄不下單跑幾週 → 模擬帳戶跑幾個月 → 再談真錢。

**③ 目前還沒有值得自動執行的策略**

這是現在唯一真正的阻礙 —— 不是技術，是**還沒有東西通過驗證**。

系統裡五個策略全數被否決，而且都輸給「買了放著」（詳見第 6、11 節）。
現在開自動交易，等於自動執行一個賠錢的規則。

> 換句話說：**車子已經造好了，還在等一個值得去的目的地。**

## 2. 三分鐘看懂整套系統

整套系統像一條生產線，資料由左往右流動：

```
 ①抓資料  →  ②算指標  →  ③模擬買賣  →  ④嚴格驗證  →  ⑤自動下單
   每天      移動平均      計算如果      這個策略      （目前關閉）
   自動        RSI       這樣買賣，     真的有效
   更新                  賺多少賠多少     嗎？
```

**關鍵觀念：兩種「自動」不要搞混**

| | 開發時的自動 | 交易時的自動 |
|---|---|---|
| 誰在做 | AI 幫忙寫程式、改程式 | 你的程式自己抓資料、自己決定買賣 |
| 什麼時候 | 開發階段 | 每天固定時間，無人看管 |
| 用什麼 | AI | **純程式，完全不用 AI** |

交易的那一段**刻意不使用 AI**。因為 AI 每次的判斷可能不一樣，事後你無法回答「為什麼那天早上十點半它買了？」。
純程式則是：同樣的資料進去，永遠得到同樣的決定，三個月後也能重播驗證。

## 3. 第一次安裝

> 只需要做一次。之後每天都是自動的。

### 需要準備

- Windows 電腦
- Python 3.10 以上（在命令提示字元輸入 `py -3 --version` 可以確認）

### 安裝步驟

**步驟 1：** 開啟「命令提示字元」或「終端機」，切換到專案資料夾

```bash
cd E:\CODE\stock-lab
```

**步驟 2：** 建立獨立的執行環境（避免影響電腦上其他程式）

```bash
py -3 -m venv .venv
```

**步驟 3：** 安裝需要的套件

```bash
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

**步驟 4：** 確認一切正常（應該看到「40 passed」）

```bash
.venv\Scripts\python.exe -m pytest -q
```

**步驟 5：** 第一次抓資料並產生報表（第一次會比較久，約 1～2 分鐘）

```bash
.venv\Scripts\python.exe scripts\dashboard.py
```

完成後，資料夾裡會出現 **`dashboard.html`**，用滑鼠點兩下就能在瀏覽器打開。

## 4. 日常使用

### 每天自動更新（已經設定好了）

系統已經在 Windows 工作排程器裡建立一個排程，名稱是 **`stock-lab-daily-update`**，
**每天下午 6:00** 自動執行：抓最新股價 → 重新計算 → 更新 `dashboard.html`。

你什麼都不用做，隔天打開 `dashboard.html` 就是最新的。

> **為什麼是下午 6 點？**
> 美股在台灣時間凌晨 4 點收盤。下午 6 點執行時，前一天的資料已經完全確定，
> 而當天的盤還沒開，資料最乾淨。

**注意：** 電腦關機時排程不會執行。但這不影響正確性 —— 系統每次都會重抓最近 7 天的資料，
所以漏掉的那幾天，下次執行時會自動補回來。

### 手動更新

想立刻更新，執行：

```bash
.venv\Scripts\python.exe scripts\update.py
```

### 檢查系統有沒有正常運作

打開 **`update.log`**，最下面幾行是最近的執行紀錄：

```
2026-08-04 14:54:15  11 symbols  newest bar 4d old  -> dashboard.html
```

意思是：11 檔股票都更新了，最新的資料是 4 天前的，報表已重新產生。

## 5. 儀表板怎麼看

用瀏覽器打開 `dashboard.html`。畫面由上往下分成幾區：

### 5.1 觀察清單（Watchlist）

最上面的表格，一次看完全部 11 檔的概況。

| 欄位 | 意思 | 怎麼看 |
|---|---|---|
| **Symbol** | 股票代號與公司名稱 | 點任一列，下方圖表就會切換到那一檔 |
| **Last** | 最新收盤價（美元） | |
| **1D / 1M / 1Y** | 一天／一個月／一年的漲跌幅 | 綠色為漲、紅色為跌；數字前面也有 +／− 符號 |
| **RSI 14** | 相對強弱指標，0～100 | 高於 70 偏「買太多」，低於 30 偏「賣太多」 |
| **Trend** | 趨勢方向 | ▲ up 表示短期均線在長期均線之上；▼ down 相反 |

> RSI 和 Trend 都只是**現況描述**，不是買賣建議。

### 5.2 篩選列

- **Symbol**：切換要看哪一檔（和點觀察清單效果相同）
- **Range**：時間範圍，1Y／3Y／5Y／All（全部）
- **Focus**：下方數字要顯示哪一個策略的結果

**這一列會同時影響下面所有圖表和表格**，數字永遠一致。

### 5.3 數字方塊

- **左邊大數字**：所選策略的**總報酬率**
- 右邊依序是：年化報酬率、最大回撤、夏普值、交易次數、手續費總額

### 5.4 圖表

| 圖表 | 看什麼 |
|---|---|
| **Equity curve（資產曲線）** | 假設一開始投入 10 萬美元，資產隨時間變化 |
| **Drawdown（回撤）** | 距離歷史最高點跌了多少 %。**看痛苦程度用這張** |
| **Price & moving averages** | 股價與 20 日、50 日移動平均線 |
| **RSI (14)** | 相對強弱指標的變化 |

**操作技巧：** 把滑鼠移到圖上，會出現一條垂直線和數字框，顯示那一天所有數值。
資產曲線和回撤圖是**連動**的，滑鼠移到其中一張，另一張會同步。

> **為什麼回撤要單獨畫一張圖，不畫在同一張？**
> 兩種不同單位的數字硬畫在同一張圖上（左右各一個刻度），
> 兩條線的相對位置是人為決定的，會讓人看出根本不存在的關聯。這是最常見的圖表錯誤。

### 5.5 下方三個表格

| 表格 | 用途 |
|---|---|
| **Chart data** | 圖上每一個數值的文字版。不想用滑鼠慢慢找時看這裡 |
| **Strategy comparison** | 兩個策略的績效並排比較 |
| **Trades** | 每一筆模擬交易的日期、買賣、股數、價格、手續費 |

## 6. 策略驗證報告怎麼看

**這是整套系統最重要的功能。** 執行：

```bash
.venv\Scripts\python.exe scripts\research.py SPY
```

（需要約 2～5 分鐘，過程中畫面不會有反應，屬正常）

### 報告長這樣

```
strategy                 folds trials  OOS ret  sharpe   maxDD   keep   DSR
SMA crossover               17    136   114.2%    0.74  -21.7%    67%  0.21
Time-series momentum        17     51    54.5%    0.44  -30.2%    57%  0.16
Vol-targeted momentum       17    102    72.1%    0.66  -16.3%    80%  0.49
RSI mean reversion          17    153    11.5%    0.16  -28.6%    56%  0.03
Donchian breakout           17     68   119.0%    0.95   -9.1%    96%  0.53
---------------------------------------------------------------------------
Buy & hold (benchmark)       -      1   216.4%    0.80  -33.7%      -     -
```

### 每一欄的意思

| 欄位 | 中文 | 怎麼判斷 |
|---|---|---|
| **trials** | 試過幾組參數 | **數字越大，結論越不可信**（見下方說明） |
| **OOS ret** | 沒看過的資料上的報酬率 | 要跟最下面那行比較 |
| **sharpe** | 夏普值（承擔風險換到多少報酬） | 越高越好，1.0 以上算不錯 |
| **maxDD** | 最大回撤 | −30% 表示中途最慘賠掉三成 |
| **keep** | 保留率 | 50～70% 算健康；太低表示以前的好績效是假的 |
| **DSR** | 校正後夏普值 | **低於 0.95 就不算證據**，不管報酬多漂亮 |

### 為什麼 trials 越多越糟？

假設你丟 100 次硬幣，總會有幾次連續五次正面 —— 但那不代表你會丟硬幣。
測試策略也一樣：**參數試得越多，越容易「碰巧」找到一組漂亮的數字。**

研究顯示，**只要試三組參數，就足以做出一個看起來很顯著、實際上毫無用處的策略**。

`DSR`（校正後夏普值）就是在做這件事：它會依照你試了幾次，**自動提高及格標準**。
試 68 次找出來的好成績，門檻就比試 3 次高得多。

### 最下面那一行才是關鍵

**Buy & hold（買進並持有）216.4%** —— 也就是「什麼都不做，買了就放著」。

上面五個策略，**最好的一個也只有 119.0%，不到它的一半。**

> 一個策略贏得了「零」，卻輸給「什麼都不做」，那不是本事，
> 只是用比較貴的方式，持有比較少的市場。

### 進一步的驗證：換一批股票再測一次

上面的表只測了 SPY 一檔。問題是，**這些策略的參數範圍是我看著 SPY 挑的** ——
就算程式本身沒有偷看未來，「挑哪些參數來試」這個動作本身就帶有事後諸葛的成分。

所以又做了一次更嚴格的測試（`scripts\research_universe.py`）：
把表現最好的兩個策略，拿到**另外十檔股票**上重跑，那十檔完全沒有參與過參數的挑選。

由於那十檔本身有倖存者偏誤（見第 8 節），比較方式是
**每一檔都跟「同一檔股票買了放著」比** —— 兩邊帶著一樣的偏誤，就互相抵消了。

結果：

| 策略 | 報酬贏過「買了放著」 | 夏普值贏過 | 回撤比較淺 |
|---|---|---|---|
| SMA 均線交叉 | **1／10** | 1／10 | 7／10 |
| Donchian 突破 | **0／10** | 0／10 | 9／10 |

**Donchian 在 SPY 上的好成績，換到別的股票完全重現不出來 —— 十檔全輸。**
SMA 唯一贏的那一檔是 NVDA，也就是這批股票裡漲勢最兇的一檔。
十次裡贏一次、而且贏在最有利的那一檔 —— 這正是「碰巧」該有的樣子。

### 最值得記住的一件事：回撤比較淺，不代表比較厲害

兩個策略在多數股票上「回撤比較淺」（7／10 和 9／10），但報酬都輸一大截。

這不是本事，這是**空手的時間比較多**：部位少 → 波動小 → 賺得也少。

同樣的效果，你只要「少買一點指數」就能免費得到 ——
不需要任何策略、不用付手續費、也不用維護程式。

> 以後只要看到「風險調整後的表現比較好」，第一個要問的是：
> **它是不是只是持有得比較少而已？**

## 7. 自動下單與安全機制

### 現在的狀態：**功能完成，但預設關閉**

原因很單純：**目前沒有任何策略通過驗證**。
現在開啟自動下單，等於是自動執行一個表現輸給「買了放著」的策略。

### 四道安全防線

系統設計成**每一層預設都是「不交易」**：

| 防線 | 說明 |
|---|---|
| **1. 預設不下單** | 程式會完整計算、完整記錄「它想做什麼」，但一張單都不會送出 |
| **2. 緊急停止檔** | 在專案資料夾建立一個名為 `HALT` 的空檔案，程式下一輪就會停止 |
| **3. 風險上限** | 單筆金額、每日筆數、單日虧損上限，任一超過就**整輪取消** |
| **4. 全程紀錄** | 每一次判斷都寫進 `journal.jsonl`，可事後核對 |

**關於第 2 點：** 建立檔案這個動作，你在慌張的時候、用任何裝置都能做到，
不需要改程式、不需要重開。這是刻意的設計。

**關於第 3 點：** 超過上限時**整輪取消，而不是把單子改小**。
因為策略要求一個離譜的數字代表程式有 bug，把它縮小成「只是有點糟」等於把 bug 藏起來。

### 只能連模擬帳戶

系統只支援 Alpaca 的**模擬交易帳戶**。這不是設定選項 ——
程式在啟動時就會檢查網址，**只要不是模擬帳戶的網址就直接拒絕啟動**。
無法靠改一行設定變成真錢交易。

### 試跑看看（安全，不會下單）

```bash
.venv\Scripts\python.exe scripts\trade.py SPY
```

會顯示：目前資產、持有部位、策略想要的目標、它「本來會下」的單，以及結果說明。

### 緊急停止的操作

在 `E:\CODE\stock-lab` 資料夾裡，**新增一個名稱為 `HALT` 的空白檔案**（沒有副檔名）。
下一輪執行時就會停止，並在紀錄裡寫下原因。想恢復，把檔案刪掉即可。

## 8. 追蹤清單說明

目前追蹤 **11 檔**：大盤指數 SPY，加上 2026 年美國最賺錢的十家公司。

| 排名 | 代號 | 公司 | 排名 | 代號 | 公司 |
|---|---|---|---|---|---|
| 基準 | SPY | 標普 500 指數 ETF | 5 | BRK-B | 波克夏海瑟威 |
| 1 | GOOGL | Alphabet（Google） | 6 | META | Meta（Facebook） |
| 2 | NVDA | 輝達 | 7 | AMZN | 亞馬遜 |
| 3 | AAPL | 蘋果 | 8 | JPM | 摩根大通 |
| 4 | MSFT | 微軟 | 9 | XOM | 埃克森美孚 |
| | | | 10 | BAC | 美國銀行 |

### ⚠️ 這份清單**不可以拿來做策略驗證**

這是一個容易忽略、但會讓所有結論失效的陷阱：

> 這份名單是「**現在**最賺錢的公司」，是**看著結果挑出來的**。
> 2015 年的名單長得不一樣，裡面有些公司後來表現很差。
>
> 拿這 10 檔去回測 2015～2026 年，成績一定漂亮 —— 因為你**事先就知道誰會贏**。
> 這叫「倖存者偏誤」，得到的數字沒有意義。

**所以：**

- ✅ **往前追蹤沒問題** —— 這就是觀察清單的用途
- ❌ **不要用它們驗證策略** —— 驗證請用 SPY

這個警告同時寫在程式碼、README 和儀表板畫面上，避免日後有人不小心踩到。

## 9. 疑難排解

### 儀表板顯示的日期是好幾天前

**通常是正常的。** 週末、美股假日都不會有新資料。
系統定義**超過 5 天**才算異常（`update.log` 會出現 `STALE` 字樣）。

### `update.log` 出現 `dropped 1 unpriced session`

**正常現象，不用處理。**

資料來源（Yahoo）有時會先給出「成交量」，但「還原後的股價」還沒算好，
於是那一天的價格是空的。系統會**丟掉那一筆並記錄下來**，下次執行時如果對方補好了就會自動抓回。

> 為什麼要記錄而不是安靜地丟掉？
> 因為安靜丟掉的話，「資料來源壞掉」看起來會跟「那天市場很安靜」一模一樣。

### 執行時出現 `no data returned` 或某檔股票抓不到

單一檔失敗**不會影響其他檔**，系統會跳過它並記錄。
如果同一檔連續好幾天都失敗，可能是代號變更或下市，需要修改追蹤清單。

### 儀表板打不開或空白

1. 確認 `dashboard.html` 檔案存在且大小約 1.8 MB
2. 重新產生：`.venv\Scripts\python.exe scripts\dashboard.py`
3. 換一個瀏覽器試試（Chrome、Edge 都可以）

### 排程沒有執行

- 確認執行時間（下午 6:00）電腦是開機的
- 在「工作排程器」中找到 `stock-lab-daily-update`，看「上次執行結果」是否為 `0`
- 手動執行一次確認程式本身正常

### 想停掉每天自動更新

```bash
schtasks /delete /tn "stock-lab-daily-update" /f
```

## 10. 名詞解釋

| 名詞 | 白話解釋 |
|---|---|
| **回測（Backtest）** | 拿歷史資料模擬「如果當時這樣買賣，結果會怎樣」 |
| **樣本外（Out-of-sample, OOS）** | 用「策略沒看過的資料」來測試。**只有這種成績才有參考價值** |
| **前推驗證（Walk-forward）** | 用前三年決定參數 → 用接下來半年檢驗 → 往前滾動、重複。本系統採用的方法 |
| **夏普值（Sharpe）** | 每承擔一分風險，換到多少報酬。越高越好 |
| **最大回撤（Max Drawdown）** | 從最高點跌下來最深的幅度。代表「最痛的時候有多痛」 |
| **倖存者偏誤** | 只看活下來的贏家，忽略已經消失的輸家，得出過度樂觀的結論 |
| **過度配適（Overfitting）** | 參數調到剛好符合歷史資料，換到新資料就失效 |
| **滑價（Slippage）** | 下單時實際成交價格比預期差的部分。本系統設定 0.05% |
| **手續費（Fee）** | 每筆交易的成本。本系統設定 0.01% |
| **移動平均線（SMA）** | 最近 N 天收盤價的平均。20 日線比 50 日線更敏感 |
| **RSI** | 相對強弱指標，0～100，衡量短期漲多還是跌多 |
| **模擬交易（Paper trading）** | 用真實市場價格、假的錢下單。練習與驗證用 |
| **部位（Position）** | 目前持有多少股 |
| **再平衡緩衝（Rebalance band）** | 偏離不到 2% 就不調整，避免每天為了小數點交易而付掉一堆手續費 |

## 11. 目前狀態與已知限制

### 完成度

| 階段 | 狀態 | 說明 |
|---|---|---|
| ①　資料抓取 | ✅ 完成 | 2015 年至今、每日自動更新、含品質檢查 |
| ②　回測引擎 | ✅ 完成 | 結構上不可能偷看未來、必定計入成本 |
| ③　策略驗證 | ✅ 完成 | 五個策略在 SPY 上全數未通過；表現最好的兩個換到另外十檔重測，也全數未通過 |
| ④　自動下單 | ✅ 完成但關閉 | 只支援模擬帳戶，預設不下單 |

**測試覆蓋：** 55 項程式測試 + 23 項畫面檢查，全數通過。

### 已知限制（重要）

1. **目前沒有可用的策略。** 這是最大的限制。機器已經蓋好，但還沒有值得放上去跑的東西。
   而且經過第二輪、換股票的驗證之後，**這個結論比之前更確定，不是更樂觀**。
2. **策略種類仍然偏少。** 標的已從一檔擴充到十一檔，但只試過五種策略想法。
3. **假設可以買零股。** Alpaca 支援，但其他券商不一定。
4. **假設下單一定成交、不影響價格。** 對大型股沒問題，冷門股會過於樂觀。
5. **現金利息預設為 0。** 這會**低估**那些常常空手的策略，屬於保守估計，不會高估。
6. **一天只更新一次。** 不適用於當沖或盤中策略。

### 建議的下一步

1. 讓自動下單以**只記錄不下單**的模式跑幾週，確認流程沒問題
2. 尋找新的策略想法時，**先想清楚「為什麼這件事會有效」**，再寫程式驗證。
   目前這五個都是「圖形規則」，沒有經濟上的理由，這可能正是它們失敗的原因
3. 增加新策略時，**刻意減少參數組合數量** —— 試得越少，結論越有力
